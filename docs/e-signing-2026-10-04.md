# Electronic signing, 4 October 2026

Ernest asked for a way to upload a document in the CMS and send it for
electronic signature. His documents already have a signature section, so the
system reads that section and lets each person sign in their own place, rather
than asking him to draw boxes on every PDF.

## How it works

1. **CMS, Documents to sign** (CRM & Sales). Upload a PDF, list who signs it
   (name, email, and optionally role, company and job title), save.
2. On save the PDF's signature section is read (`cms/src/lib/signing/detect.ts`)
   and each place is matched to a signer (`assign.ts`). The panel at the top of
   the request lists every place with a dropdown to change the match.
3. **Send**. Each signer gets a private link to `quademdigital.com/sign/<token>/`
   by email. The panel also has "Copy link" for sending by WhatsApp.
4. The signer reads the document on the page, taps each yellow box, draws or
   types their signature once (and initials once, if the document asks), ticks
   the consent box and signs. Name, date and job title places fill themselves.
5. When the last person signs, the PDF is stamped (`stamp.ts`): every signature,
   initials, name and date goes into its place, a reference line goes in the
   bottom margin of every page, and a **signing certificate** is added at the
   end. Everyone, Ernest included, is emailed the signed copy as an attachment.
   It is also kept in **Signed documents**, which nobody can edit or delete.

Options per request: ask for a code (a six-digit code emailed when the link is
opened, so a forwarded link is useless), sign one after another, how long the
link works (30 days), and automatic reminders (every 3 days, at most three).
Ernest can send a reminder or withdraw a request at any time from the panel. A
signer can decline, with a reason, which ends the request and tells everyone.

## What the detector reads

Tested against the three real agreements, with the result checked by eye:

| Document | Layout | Found |
| --- | --- | --- |
| Omek service agreement | "Signature" label below a drawn line, two columns (SERVICE PROVIDER, CLIENT) | both signatures, the client's name, both dates |
| Citywide agreement | inline "Signature: ____", "Date: ____", plus a witness block per party | both signatures, dates, the client's name and position, both witnesses' names and signatures |
| Charles's Business Development Agreement | letter-spaced labels above an empty space, witness blocks, "Initials: Company ____ Trainee ____" on every page | both signatures, both dates, both witnesses, initials on pages 2 to 7 |

Signature lines are drawn shapes, not text, so the labels are what is read, and
each box is snapped to the nearest drawn line in its column. Whose column it is
comes from the words around it ("CLIENT", "For Citywide Property Services
Ltd", "THE TRAINEE · Charles Ohanu"). A place nobody is matched to stays blank;
a signer with no place in the document signs on the certificate page instead.

## The certificate

The last page records the reference, the document's SHA-256 fingerprint as
sent, when it was sent and completed, each signer's signature, email, time,
IP address and device, how they were identified (the email link, and the code
if one was asked for), and the full history. The fingerprint lets anyone check
the signed copy came from exactly the document that was sent.

## Decisions worth keeping

- **Each signer's progress is its own record** (`signing-sessions`), not a row
  inside the request, so two people signing in the same second cannot
  overwrite each other's signature. Finishing is guarded by one conditional
  `UPDATE ... WHERE status = 'out'`, so it runs exactly once.
- **Links are stored as a hash** (for lookup) and sealed with a key derived from
  `PAYLOAD_SECRET` (so Ernest can copy them). A copy of the database is not a
  set of working links.
- **"Opened" is recorded by the page's own script**, not when the website
  renders it. Gmail, Outlook and WhatsApp fetch every link to preview it, and
  the certificate should not say Microsoft's link scanner opened the contract.
- **The signing page loads nothing from elsewhere.** It does not use
  BaseLayout, because Tag Manager, Analytics, Ahrefs, Metricool and the chat
  widget would each record the private link. pdf.js is self-hosted in
  `public/vendor/pdfjs`; the typed signature uses Dancing Script, self-hosted.
- **Signing links use `quademdigital.com`, not `ASTRO_SITE_URL`**, which is
  `http://localhost:4321` on Railway. `SIGNING_SITE_URL` overrides it for tests.
- **`/sign` is never cached** at the edge (`src/middleware.ts`).
- **Finishing runs after the signer gets their answer**, because stamping and
  emailing three copies can outlast the website's request time limit. The
  five-minute job (`signingRounds`) finishes anything a restart cut short,
  expires old requests and sends the reminders.
- **Once sent, nothing can change** except the client and team member links. A
  mistake is fixed by withdrawing and sending a new request. A completed
  request cannot be deleted.
- Files go in the private documents bucket under their own prefixes
  (`signing/`, `signed/`), because the bucket is shared and Payload only keeps
  filenames unique within one collection.

## Found while building it

- `ASTRO_SITE_URL` on Railway is localhost: every signer would have been sent a
  link to `http://localhost:4321`.
- The generated migration's `down()` failed: it dropped the lock-table
  constraints by name after `DROP TABLE ... CASCADE` had already removed them.
  Caught by `cms/scripts/rehearse-migration.mjs`, new, which runs up, down and
  up again against production inside a transaction that is always rolled back.
- `signing_sessions.request_id` came out `NOT NULL` with `ON DELETE SET NULL`,
  so deleting a withdrawn request would have failed. It is `CASCADE`.
- `migrate:create` wrote a macOS `._` sidecar into `src/migrations/index.ts` as
  if it were a migration. The Docker build excludes `._` files, so production
  would have failed to build. Caught by building the CMS locally.
- pnpm refuses to update the lockfile without deleting and reinstalling
  `node_modules` on this drive. The lockfile was generated in a scratch copy,
  merged so that nothing was removed (pnpm 9 drops the `libc` lines a newer
  pnpm wrote), and checked with `pnpm@9.15.4 install --frozen-lockfile`, the
  Docker build's own command.

## Not covered yet

- Word documents. Save as PDF first; converting server-side needs LibreOffice
  in the image.
- Drawing boxes by hand for a document with no signature section. Those sign on
  the certificate page.
- Blanks outside the signature section (contact person, start date) are not
  filled in. Fill them before uploading.
